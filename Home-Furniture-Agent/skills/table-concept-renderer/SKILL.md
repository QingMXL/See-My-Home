# Table concept renderer

Read `references/visualization-contract.md` before calling any visual generation or publication tool.

## Execution

1. Read `request.output_mode` first. Start from the validated table design specification, not from an improvised prompt.
2. For `orthographic_sheet`, use `render_asset_ref` as the sole visual source and `confirmed_design_spec` as immutable structured truth. Skip the weighted-reference rules below and follow the orthographic section in the visualization contract.
3. For `concept_render`, when both images exist, reflect `source_priority` in the prompt and specification: stay closer to the higher-weight image and retain proportionally fewer cues from the lower-weight image. At equal weights, synthesize both.
4. For `concept_render`, when only one image exists, use it as the sole visual reference. Do not reproduce logos or copy a branded product wholesale.
5. Build one English image prompt for the requested mode. A product-render prompt states the dimensions, components, materials, finish, camera viewpoint, and prohibited changes. An orthographic prompt requests only `request.orthographic_view`: one complete pure black-on-white front, side, or top line-art raster with clear margins for application-rendered annotations. Require standard furniture technical-drawing line hierarchy: a clearly heavier visible outer contour and thinner internal component lines. For `top`, require a strict top plan with the camera axis perpendicular to the tabletop, the tabletop parallel to the image plane, no perspective or adjacent faces, and only surfaces genuinely visible from directly above. Opaque upper surfaces occlude every lower component; do not show hidden base parts with solid or dashed lines.
6. Call the available ZooWork image-generation capability exactly once using only arguments exposed by the current tool schema. Do not invent model, provider, numeric image-weight, or control-strength arguments.
7. Call `sessions_yield` exactly once and end the waiting run. In ZooWork's attachment continuation, materialize the returned image, inspect it once, and compare it with the applicable visual source and specification.
8. For concept renders, publish only when the raster is readable and passes the mode checks. For an orthographic turn, publish only one readable, complete requested view that recognizably matches the confirmed component inventory and uses the required heavy-outline/thinner-detail hierarchy. Cropping, multiple views, perspective-only output, corrupt output, missing major components, materially different furniture, tonal shading, material texture, visible hidden structure, or uniformly faint construction strokes fail. For `top`, also fail any bird's-eye angle, skewed plan, visible tabletop thickness, visible front/side/underside face, hidden structure drawn through an opaque top, or unsupported base projection beyond the tabletop footprint. Minor raster proportion drift alone does not fail the orthographic artifact only after projection and visible-surface correctness pass.
9. Return one compact JSON response matching the supplied response schema. For `orthographic_sheet`, echo `confirmed_design_spec` unchanged in `response.design_spec`, set `qa.orthographic_projection_correct` and `qa.orthographic_visible_surfaces_correct` explicitly, and publish only when both are true.

For `concept_render`, do not ask the image model for drawings. For `orthographic_sheet`, create only the single view named by `request.orthographic_view`, without generated text, dimensions, borders, a title block, or manufacturing claims. The application runs three independent turns and composes their results into one 4K shop-drawing PNG carrying exact annotations from the confirmed specification: front width/height, side depth/height/top thickness, and top width/depth. Aim for the relevant confirmed proportion and keep clear margins around the complete object. Set `qa.dimensions_consistent=true` when the structured specification is echoed unchanged; use warnings, rather than failure, only for minor correctable raster ratio drift.
